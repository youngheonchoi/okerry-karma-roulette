# 모바일 UI 보완 및 작은 다크 테마

- 작업일: 2026-11-11
- 요청: 앱인토스용 모바일 화면 호환, 전체 폰트와 UI 축소, 다크 화면 콘셉트.
- 기존 React DOM과 자체 보라색 토큰을 유지했다. TDS 패키지를 설치하거나 토스 전용 서체·로고를 사용하지 않았다.

## 화면 변경

- 기본 본문 16 → 15px, 제목 28 → 22px, 섹션 제목 21 → 17px.
- 첫 화면 제목은 쉼표 없이 `오늘 계산` / `업보로 정해볼까요?`를 왼쪽 정렬 두 줄로 표시하고 30px로 강조한다. 제목과 카드 사이에는 96px 여백을 둔다.
- 두 카드 오른쪽 아래에는 직접 작성한 SVG 룰렛과 `1/N` 그림을 배치한다. 그림 일부가 모서리 밖으로 잘리고 오른쪽 아래로 갈수록 마스크 그라데이션으로 흐려진다. 장식은 터치·초점·접근성 이름에 영향을 주지 않는다.
- 모드 카드는 두 개의 정사각형을 가로로 배치한다. 주요 버튼 56 → 48px, 일반 버튼·입력 최소 높이 44px. 카드·목록·질문·확인창의 여백과 룰렛 크기도 줄였다.
- 첫 화면에는 두 줄 제목과 `한명뽑기`·`N빵하기` 정사각형 카드만 표시한다. 카드의 기존 이름과 설명은 제거했다. 카드를 누르면 해당 모드를 저장하고 바로 참가자 설정으로 이동한다. 가로 두 칸 배치와 다크 테마를 유지한다.
- 차콜 배경, 밝은 본문, 회색 보조 문구, 보라색 포인트의 다크 테마를 추가했다. 입력·선택·오류·비활성·확인창·룰렛 번호를 테마 토큰에 연결했다.
- 글자 크기는 rem을 사용해 확대 시 함께 커진다. 참가자 편집 행과 긴 이름·질문의 줄바꿈을 보완했다.
- 룰렛 번호는 고정 반경 대신 원판 크기에 비례한 위치를 사용한다.
- 뷰포트의 크기 변화, 사방 안전 영역, 가로모드와 짧은 높이의 확인창 스크롤을 대응했다. OS 키보드를 제한하거나 페이지 확대를 막지 않았다.
- 앱인토스의 기본 상단바와 중복되는 앱 내부 브랜드 헤더를 제거했다.
- Chromium 검증에서 발견한 새로고침 이탈을 수정했다. StrictMode에서 효과가 두 번 실행돼도 탐색 표식을 동기적으로 지워 history.back()을 한 번만 호출한다.

## 다크 미리보기와 출시용 라이트

사용자가 전달한 [TDS 컴포넌트 안내](https://developers-apps-in-toss.toss.im/design/components)를 확인했다. [공식 디자인 도구 안내](https://developers-apps-in-toss.toss.im/design/prepare/design)와 [FAQ](https://developers-apps-in-toss.toss.im/guide/faq)는 현재 라이트 모드 기준 디자인·출시를 안내한다.

- `npm run dev` / `npm run build`: 요청한 다크 콘셉트.
- `npm run build:toss`: 같은 작은 UI를 라이트 테마로 출력. HTML의 data-theme, theme-color, color-scheme도 함께 변경한다.
- `build:toss`는 웹 산출물 생성 명령이다. 앱인토스 SDK 통합, `.ait` 번들 생성, 업로드·출시를 수행하는 명령은 아니다.

## 검증

- WebKit / Chromium 모바일 에뮬레이션에서 브라우저 테스트 총 36개 통과(레이아웃·동작 34개, 기본 크기·두 테마 대비 2개).
- 320×568, 360×640, 390×844, 430×932, 568×320, 768×360과 기본/200% 글자 크기.
- 설정 → 전달 → 질문 → 룰렛 → 결과 → 재진행 확인창. 12명·긴 이름, N빵 최대 입력값과 정산 보류 화면, 비대칭 안전 영역, 짧은 뷰포트, 새로고침·뒤로가기.
- 가로 넘침·버튼 문구 잘림·조작 영역 크기·작은 글자·룰렛 번호 경계를 검사했다. 두 테마에서 본문·보조 문구·오류·주요 버튼·룰렛 번호의 텍스트 대비 4.5:1 이상을 확인했다.
- `npm run typecheck`, `npm run build`, `npm run build:toss`, `git diff --check` 통과. 라이트 산출물의 테마와 메타 태그도 확인했다.
- 화면 캡처는 실제 웹 앱 렌더링 결과다. 정책 확정 이후 화면은 네트워크 응답에만 주입한 테스트 전용 정책으로 검증했고 운영 `src/policy.ts`는 null 상태를 유지했다.

## 확인이 남은 부분

- 실제 토스 앱 WebView의 SDK 안전 영역·상단바·뒤로가기 연동과 기기 키보드.
- OS 글자 확대·VoiceOver/TalkBack 낭독과 전달 시 앱 미리보기.
- 키보드는 짧아진 뷰포트로 레이아웃만 검증했으며 실제 OS 키보드를 검증한 것으로 간주하지 않는다.
- 미확정 Q01~Q08과 운영 질문·정산·공유는 이번 UI 요청에서 확정하거나 활성화하지 않았다.

공식 컨테이너 근거: [Safe Area](https://developers-apps-in-toss.toss.im/documentation/common/screen/safe-area), [네비게이션 바 설정](https://developers-apps-in-toss.toss.im/documentation/common/navigationbar). CSS 안전 영역 테스트는 레이아웃 계약 검증이며 실제 SDK 연동 검증과 구분한다.
