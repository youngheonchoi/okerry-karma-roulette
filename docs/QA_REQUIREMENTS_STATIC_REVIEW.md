## 1. 검토 범위

React 화면 연결(src/App.tsx), 상태 전이(src/session.ts), 계산·검증·공유 투영(src/domain.ts), 정책 계약(src/policy.ts), 룰렛·확인창(src/components.tsx)을 문서와 대조했다. 정적 코드 경로만 확인했으며 기능 통과 여부는 판정하지 않는다.

## 2. 발견 항목

### QAR-01 · P1 · F08 독박 동일 참가자 재진행도 정책 미승인 상태에서 무반응

- **근거:** src/App.tsx 결과 화면은 독박 모드에서 ‘같은 참가자로 다시 진행’을 활성화한다. src/session.ts의 restart(same=true)는 split 여부와 무관하게 questions 또는 inputs가 null이면 기존 상태를 반환한다. 현재 src/policy.ts는 두 값 모두 null이다.
- **영향:** 사용자가 확인창에서 초기화를 확정해도 화면은 결과에 남고 오류 안내도 없다. Q06의 미결정 범위는 N빵 금액 유지이며, 독박 재진행까지 막아야 한다는 근거를 문서에서 찾지 못했다. Q01/Q05 정책이 미승인인 현재 청문회 시작 자체가 막혀 실제 사용자 도달 경로는 제한되지만, 정책 연결 뒤에도 해당 가드가 유지되면 독박 재진행이 계속 막힌다.
- **기대:** 확인 완료 후 독박은 참가자·모드 유지, 응답·점수·결과 초기화 및 새 라운드로 이동해야 한다. N빵만 Q06 금액 정책에 따라 보류/재입력을 적용해야 한다.
- **수정 후 재검증:** 미수행.

### QAR-02 · P2 · F02 삭제 조작은 2명 하한에서 즉시 차단되지 않음

- **근거:** 참가자 행의 삭제 버튼은 인원수와 무관하게 활성 상태(src/App.tsx 참가자 목록). 삭제 후 reducer는 최대 12명만 제한하고 최소 2명 조건은 제출 검증에서만 검사한다.
- **영향:** 명단을 1명 또는 0명까지 줄일 수 있다. 다음 단계에서 시작은 막히지만, F02의 2~12명 설정 규칙이 편집 단계에서 보장되지는 않는다. 최종 검증 오류는 표시될 수 있어 잘못된 라운드 생성으로 이어지는 결함은 확인되지 않았다.
- **기대:** 2명일 때 삭제를 막거나, 삭제 결과가 2명 미만이 되지 않도록 인라인 안내를 제공한다.
- **수정 후 재검증:** 미수행.

### QAR-03 · P2 · 공유 화면으로 들어가면 결과에서 직접 재진행할 수 없음

- **근거:** F07 결과의 ‘공유 안내 보기’는 reducer를 sharing 상태로 전환한다. 공유 화면은 결과로 돌아가기만 제공하며, 재진행 버튼은 result 화면에만 있다. 브라우저 뒤로가기는 별도 state 전이로 구현되지 않았다.
- **영향:** 공유 안내를 열었다가 곧바로 재진행하려면 결과 복귀 동작이 필요하다. 화면 하단의 뒤로 버튼도 sharing에서 제외되어 있어 앱 내에서 이탈 수단이 하나뿐이며, 호스트/브라우저 뒤로 동작은 미확정이다.
- **기대:** 공유 취소·복귀 후 결과와 확정값을 보존하고 재진행을 계속 선택할 수 있어야 한다. 공유 화면의 뒤로 동작은 USER_FLOW 및 호스트 뒤로 계약과 맞아야 한다.
- **수정 후 재검증:** 미수행. 기존 UX_STATIC_REVIEW의 D01(호스트/브라우저 뒤로 정책 미연결)과 연관.

### QAR-04 · P2 · 확정 결과를 임의 action payload로 검증하지 않고 수용하는 reducer 경계

- **근거:** src/session.ts의 result action은 현재 roulette 상태, roundId, winnerId의 참가자 존재 여부만 확인하고 action.result.participants의 점수·참가자 스냅샷 일치 여부는 확인하지 않는다. UI의 Roulette 경로는 내부적으로 점수 비례 결과를 만들지만 reducer 자체 경계는 더 넓다.
- **영향:** 향후 다른 호출자/비동기 경로에서 stale 또는 조작된 결과 payload가 전달될 경우 현재 세션의 참가자·점수와 다른 결과가 저장될 수 있다. 현재 정적 화면 흐름에서 외부 입력으로 이 action을 호출하는 경로는 확인되지 않아 잠재 위험으로 분류한다.
- **기대:** 결과 수용 시 현재 roundId와 고정 참가자 ID·점수 스냅샷의 일치, 단일 확정 조건을 검증한다.
- **수정 후 재검증:** 미수행.

## 4. 기존 검토와의 연결

- docs/UX_STATIC_REVIEW.md의 D01~D06은 기존 UX 정적 리뷰에서 이미 보고된 항목이다. 특히 뒤로가기(D01), 결과 접근성 발표(D02), 입력 오류 제거(D04), N빵 재진행 설명(D06)은 이 대조에서도 구현 완료로 확인되지 않았다.
- 새로 확인한 본 보고의 QAR-01~04는 기존 보고에 동일 재현 조건으로 등록되지 않은 요구 경계다. 이 문서는 수정 적용 보고가 아니다.

**출시 판단:** 보류. 정적 코드에서 안전 보류 구조는 확인했으나, F04~F07 핵심 이용 흐름은 정책·플랫폼 미확정으로 제공되지 않으며 위 결함과 실행 미검증이 남아 있다. 이는 출시 실패 테스트 결과가 아니라 정적 검토 시점의 범위 판단이다.

## 가정

- 문서의 Q01~Q08은 모두 미결정으로 취급했고, 권고안을 운영 정책으로 승격하지 않았다.

- 기존 UX 검토 항목은 중복 결함으로 재등록하지 않고 연관 항목으로 참조했다.
