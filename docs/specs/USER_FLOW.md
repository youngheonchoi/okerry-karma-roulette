# 업보 룰렛 — 사용자 흐름 초안

- 작성: 어그(UX/UI 디자이너), 2026-11-11 / PM 제출 v0.3
- 기준: [mvp.md](../planning/mvp.md) v1.0, 상위 업무 기획서, 인수인계 기본값.
- 상태: 원문 대조 완료, 정책 승인 전 초안. 실제 화면 검토 결과가 아니다.
- 저장소 확인: 작성 전 `.git`과 `mvp.md`만 존재. 화면 코드·디자인 체계·기술 스택은 확인되지 않았다. 기존 화면 ID가 없어 아래 ID를 제안한다.
- 이 문서는 이전 임시 폴더의 ‘원문 미대조 초안’을 대체한다. PM 통합 문서와 공통 정책 ID를 대조했으며, Q01~Q08 결정 전 정책은 확정으로 간주하지 않는다.

## 1. 요구사항·가정·충돌 구분

| 구분 | 내용 | 적용 |
|---|---|---|
| 원문 확정 요구 | 정산 유틸리티, 로그인·서버·DB·실제 거래 없음, 클라이언트 처리, 2~12명 | 두 모드 전체 |
| 원문 확정 요구 | 독박 룰렛은 금액 입력 없음, 업보 N빵만 금액 입력 | F01·F03 |
| 원문 확정 요구 | 원문 질문의 다중 체크, 중복 불가·해제 가능·선택 없이 완료 가능 | F04 |
| 원문 확정 요구 | 점수 sᵢ=max(20,100+선택 점수 합), 확률/부담 비율=sᵢ/Σs | F04~F06 |
| 초안 기본값 | 닉네임1~20자·중복 금지, 총액1~99,999,999원 정수 | 상위 업무/인수인계. 최대값은 원문이 정하지 않은 보완 정책 |
| 초안 기본값 | 점수 상한 없음, 예시16문항을 문구·점수 변경 없이 초안 채택 | 원문은 상한·최종 문항을 PM 검토로 남김. Q01 |
| 초안 기본값 | 같은 참가자 재진행 시 모드·참가자·금액 유지, 응답·결과 초기화 | F08 금액 유지 여부를 보완. 점수100으로 복귀 |
| 충돌·PM 채택 필요 | N빵 원 단위 배분 권고 vs 원문의 기본100원 반올림 및 최고점자 차액 조정 검토안 | 상위 업무는 원 단위 정확성 명세 요구. 7절/Q02에 대안·결과 명시 |
| 충돌·PM 채택 필요 | F06의 ‘주요 질문’ 결과 노출 vs 휴대폰 전달 프라이버시 | 요구를 삭제하지 않고 명시적 공개 단계 제안. Q03 |
| 원문 유지 | F07 독박 공유의 당첨자 점수·확률, N빵 공유의 전체 부담금액, 서비스 링크·복사 대안 | 질문만 공유 제외. 점수까지 일괄 제외했던 임시 초안 수정 |

위 기본값은 이번 업무를 위한 초안이며, 원문에서 PM 검토 대상으로 남긴 사항을 최종 승인으로 바꾸지 않는다.

## 2. 기능↔화면 ID

| 화면 ID | 이름·목적 | 기능 |
|---|---|---|
| UX-01 | 정산 모드 선택 | F01 |
| UX-02 | 참가자 설정: 수·닉네임·랜덤 이름·추가/삭제/수정 | F02 |
| UX-02A | 총 결제 금액 입력: N빵 전용 | F03 |
| UX-03 | 참가자 호출·전달·복귀 가림 | F04 |
| UX-04 | 개인 업보 청문회: 카테고리별 다중 체크·자동 점수 | F04 |
| UX-05 | 응답 완료 확인: 전체 완료 현황만 확인 | F04 |
| UX-06 | 독박 룰렛: 가중치 영역·대기·추첨·회전 | F05 |
| UX-07 | 결과: 독박 당첨 또는 N빵 정산 내역 | F05·F06·F08 |
| UX-08 | 공유 미리보기·텍스트 공유·복사 | F07 |
| UX-D01 | 진행 중단·초기화 확인(공통 다이얼로그) | F04~F08 |

이 ID는 SCREEN_SPEC.md와 동일하다. PM은 PRD·FUNCTIONAL_SPEC·TASK_BACKLOG·OPEN_QUESTIONS의 ID를 함께 맞춘다. UX-07은 모드별 변형이며 별도 기능을 추가하지 않는다.

링스 검토 반영: 모든 `UX-` ID는 이번 초안의 제안 ID이며 기존 시스템 ID가 아니다. F03의 `UX-02, N빵 모드` 대응은 설정 단계 묶음을 뜻하며, 상세 흐름에서는 해당 하위 단계를 `UX-02A`로 구분한다. F02는 UX-02, F03은 UX-02A로 인계하며 독박 경로에는 금액 입력이 없다. F08은 UX-D01 확인 후 새 참가자 UX-01 / 동일 참가자 UX-03 진입으로 대응한다. 원문 대조와 F01~F08 매핑은 완료했으며, 미완료인 것은 정책 승인·나머지 PM 문서와의 통합·실제 UI 검증이다.

## 3. 모드별 정상 흐름

### 독박 룰렛

1. UX-01에서 `독박 룰렛` 선택 → UX-02. 금액 입력·금액 검증을 수행하지 않는다.
2. 유효한2~12명 등록 후 `업보 청문회 시작` → UX-03. 등록 순서와 질문 세트를 라운드 동안 고정한다.
3. UX-03에서 `다음은 {닉네임}님 차례예요` 및 k/n을 표시한다. 휴대폰을 전달받은 사람이 `내 질문 시작` → UX-04.
4. UX-04에서 본인에게 해당하는 항목을 다중 선택·해제한다. 점수는 전체 선택 집합으로 매번 다시 계산한다. 아무것도 선택하지 않아도 `응답 완료` 가능하며 최종100점이다.
5. `응답 완료` 성공 시 민감 UI를 제거하고 다음 사람의 UX-03. 마지막 사람이면 UX-05. 저장 실패 시 현재 사람의 입력을 보존하며 전달하지 않는다.
6. UX-05는 n/n명의 완료 상태만 보여준다. `룰렛 확인` → UX-06 대기 상태. 완료하지 않은 참가자가 있으면 해당 참가자의 UX-03으로 안내한다. 시작 전 사람을 자동 완료로 처리하지 않는다.
7. UX-06에서 참가자 이름·점수·확률·비례 영역을 확인한다. `룰렛 돌리기`를 눌렀을 때 확정 점수로 당첨자를 한 번 추첨한 뒤 그 결과에 맞게 회전·감속한다.
8. 회전 완료 이벤트를 한 번 처리하여 UX-07 독박 결과로 이동한다. 동작 감소 환경은 회전 없이 동일한 추첨 결과를 한 번 공개한다.
9. `결과 공유` → UX-08, `같은 참가자로 다시 진행` 또는 `새로운 참가자로 시작` → UX-D01.

### 업보 N빵

1. UX-01에서 `업보 N빵` → UX-02 참가자 설정 → UX-02A 총액 입력.
2. 유효한 정수 총액1~99,999,999원 확인 후 `업보 청문회 시작` → UX-03.
3. 참가자 호출·질문·완료는 독박3~5단계와 동일하다. 참가자별 빈 선택은100점으로 계산한다.
4. 전원 완료 후 UX-05에서 `정산 결과 보기`를 누르면 점수·총액 스냅샷으로 계산한다. 이 화면의 진행 상태로 표시하며 룰렛 화면은 거치지 않는다.
5. 계산 결과의 정수·비음수·합계 일치를 검증한 뒤 UX-07 N빵 결과로 이동한다. 모든 참가자의 점수·점수 비율·실제 원 단위 부담액 및 총액·합계를 표시한다.
6. 주요 질문은 F06 요구를 유지하되 Q03 공개 정책에 따라 기본 접힘 상태와 명시적 공개 안내를 제안한다. 질문은 공유 텍스트에 포함하지 않는다.
7. 공유·재진행은 독박9단계와 동일하다. 송금·결제 행동을 제공하지 않고 `참가자 간 합의에 따라 활용하는 결과`임을 알린다.

| UX-06 대기 → 뒤로 | UX-05 | 완료 응답 보존, 아직 추첨하지 않음 |

| UX-05 계산 중 → 뒤로 | 진행 중단 확인, 닫기는 가능 | 결과 생성 식별자로 중복 계산/반영 방지 |
| UX-07 → 뒤로 | UX-D01에서 유지/재진행 선택 | 응답 화면으로 직접 돌아가지 않음. 취소 시 결과 보존 |
| UX-08 → 뒤로/공유 창 취소 | UX-07 | 공유 전 결과·라운드 보존, 취소는 오류 아님 |
| 같은 참가자로 재진행 확인 | UX-03 첫 참가자 | 모드·명단·순서·N빵 금액 유지, 응답·점수·당첨·정산·질문공개 상태 초기화 |
| 새로운 참가자로 시작 확인 | UX-01 | 참가자·모드·금액·응답·점수·모든 결과·공개 상태 초기화 |

브라우저 뒤로·Android 시스템 뒤로·호스트 뒤로가기에 같은 내부 정책을 적용한다. 호스트의 닫기를 막거나 재진입을 강요하지 않는다. 앱인토스 뒤로와 자체 뒤로를 중복 표시하지 않는다.

## 5. 입력·오류·진행 상태

| 상황 | 화면 피드백 | 복구·완료 조건 |
|---|---|---|
| 참가자0/1명·13명 요청 | `2명 이상 등록해 주세요` / `최대12명까지 참여할 수 있어요` | 편집 허용·시작 차단, 12명에서 추가 비활성 사유 표시 |
| 빈/중복/20자초과 이름 | 해당 행 인라인 오류, 첫 오류로 초점 | 앞뒤공백 제거·NFC 정규화·사용자 인식 글자 수 제안(Q05). 한글 조합 중 자르지 않음 |
| 랜덤 이름 중복 | 고유 후보를 다시 선택 | 기존 수동 이름도 중복 검사. 후보 부족 시 오류·직접 입력 제공, 무한 재시도 금지 |
| N빵 금액 빈값/0/음수/소수/초과/비숫자 | `1원부터99,999,999원까지 정수로 입력해 주세요` | 입력 보존. 천 단위 구분 표시, 조용히 반올림·삭제 금지 |
| 질문 준비 오류 | `질문을 준비하지 못했어요`·재시도 | 문항을 임의 대체하지 않음. 청문회 시작을 차단 |
| 질문 체크·해제 | 즉시 선택 상태·본인 점수 갱신 | 같은 질문 ID 중복 가산 금지. 최저20점 적용 뒤 해제할 때도 전체 합산 재계산 |
| 선택0개 완료 | `선택한 항목 없음 ·100점` | 유효 정상 응답. 경고·응답 강요·누락 오류로 취급하지 않음 |
| 완료 처리 중·실패 | `응답을 반영하고 있어요` / 실패 안내 | 저장1회, 실패 시 입력 보존·재시도. 서버 저장/네트워크 요청을 추가하지 않음 |
| 전원 완료 전 결과 요청 | 남은 참가자 수와 `응답 이어가기` | 완료 없는 사람을100점으로 자동 확정하지 않음 |
| 독박 추첨·회전 중 | `룰렛이 돌아가고 있어요` | 시작 버튼 중복 차단, 표시% 대신 원점수 비율로 추첨, 결과 발표1회 |
| N빵 계산 중 | `정산 금액을 계산하고 있어요` | 실제 의존성 없는 장시간 로딩·가짜% 금지 |
| 결과 검증 오류 | `정산 금액을 계산하지 못했어요. 다시 시도해 주세요` | 음수·합계오차·소수는 성공 결과/공유 금지. 기존 확정 결과가 있으면 덮어쓰지 않음 |
| 공유 미지원·실패 | `텍스트 복사` 제공 | 복사 성공 확인 후만 완료 알림, 권한 거부/실패 시 텍스트 선택·수동 복사 대안 |
| 공유 취소 | 원래 결과로 복귀 | 오류/성공 단정 금지, 재추첨·초기화 금지 |
| 상태 유실·새로고침 | 메모리 기본안은 UX-01에서 새 시작 | 영속 저장 미확정(Q06). 실패 복구로 다른 당첨자를 자동 생성하지 않음 |

## 6. 프라이버시·공유 경계

- 개인 응답→전달에서는 질문·선택·점수 DOM과 접근성 트리를 제거한 후 다음 닉네임을 표시한다. CSS 블러/투명만으로 숨기지 않는다. 포커스·오류·토스트에도 이전 답변을 남기지 않는다.
- UX-03은 다음 닉네임·순서·준비 CTA만, UX-05는 완료 여부만 표시한다. 점수·질문 공개는 결과 단계의 별도 정책이다.
- 본인 인증 없는 한 기기 전달 방식이므로 다른 사람이 준비 버튼을 누르거나 옆에서 보는 행위·OS 캡처를 완전히 차단한다고 안내하지 않는다.
- F06의 주요 질문은 삭제하지 않는다. 추천안은 기본 비공개 상태에서 참여자에게 `모두가 볼 수 있어요`를 알린 뒤 별도 `주요 질문 공개` 조작으로만 펼치는 방식이다. 인증 없는 동의는 보호 한계가 있어 Q03의 PM 채택이 필요하다.
- 공유 payload는 아래 표의 항목만 허용한다. 질문·질문 ID·선택 내역·개별 답변을 텍스트/URL 파라미터/로그에 포함하지 않는다. 수동 복사에도 같은 필터를 적용한다.

| 모드 | 원문 필수 공유 항목 | 제외 |
|---|---|---|
| 독박 룰렛 | 참가자 목록, 최종 당첨자, 당첨자 점수·확률, 서비스 링크 | 질문·응답, 다른 참가자 점수는 기본 제외 |
| 업보 N빵 | 총 결제 금액, 참가자별 부담 금액(식별용 닉네임 포함), 서비스 링크 | 질문·응답·점수·비율은 기본 제외 |

링크는 개인 결과를 복원하는 링크가 아니라 서비스 진입 링크다. 결과는 공유 텍스트에 있다. 웹 공개 URL과 앱인토스 정식 링크는 실제 배포값 확인 후 지정한다. 임의 도메인·테스트 `intoss-private://` 링크를 넣지 않는다. 링크가 설정되지 않으면 공유 준비 오류를 표시하고 출시 전 필수 설정으로 남긴다.

## 7. 계산과 표시의 경계

1. 점수는 sᵢ=max(20,100+Σ선택문항점수), W=Σsᵢ. 최소점수가 양수이므로2~12명 유효 참가자의 W는0보다 크다.
2. 독박의 실제 추첨·영역각은 원점수 비율 sᵢ/W, 표시 확률은100sᵢ/W를 소수 둘째 자리까지 표시한다. 표시% 합은 반올림으로100%와 다를 수 있어 설명한다. 합을 맞추려고 추첨 확률을 바꾸지 않는다.
3. N빵 권고안(Q02): 총액 T원에 대해 bᵢ=floor(Tsᵢ/W), 잔여 R=T−Σbᵢ. 나머지 (Tsᵢ mod W)가 큰 참가자부터1원씩 R명에게 배분, 동률은 등록순서. 모든 값은 정수, 합계T·음수없음·동일입력 동일배분을 만족한다. 정확한 정수 비교를 사용하며 부동소수점 표시값으로 정렬하지 않는다.
4. 이는 원문의100원 단위 정책 변경이므로 최종 승인으로 간주하지 않는다. 대안은100원 반올림 후 차액을 최고점자부터 등록순으로 보정하되 음수 발생 시 다음 참가자로 넘기는 방식이다. 다만100원 미만 금액과 총액 보존 때문에 예외가 생긴다. FUNCTIONAL_SPEC에서 하나를 명시 채택해야 한다.
5. N빵 점수비율은 반올림 보정 전 비율, 부담액은 보정 후 실제 금액임을 구분한다. 화면과 공유는 같은 확정 금액 배열을 사용한다.

원 단위 권고안 검증 예:

| 총액·점수(등록순) | 기대 금액 | 근거 |
|---|---|---|
| 1원·100점×12명 | 1번1원, 나머지0원 | 최소총액·동률·개인0원 허용 |
| 101원·100점×3명 | 34,34,33원 | 동일 나머지 등록순2명에1원 |
| 100원·150/100/50점 | 50,33,17원 | 마지막 참가자의 나머지가 더 큼 |
| 99,999,999원·100점×12명 | 1~3번8,333,334원, 나머지8,333,333원 | 최대총액·합계 보존 |
