# 업보 룰렛 — 제품 요구사항 정의서(PRD)

- 버전: 0.1 / PM 통합 초안
- 기준: [mvp.md](mvp.md) v1.0, [USER_FLOW.md](../specs/USER_FLOW.md) v0.3, [SCREEN_SPEC.md](../specs/SCREEN_SPEC.md) v0.3
- 상태: 원문 요구와 초안 정책을 통합한 검토본. 미확정 항목 Q01~Q08은 승인된 정책이 아니다.
- 프로젝트 코드·기술 스택·디자인 시스템은 확인되지 않았다. 구현 기술을 임의 지정하지 않는다.

## 1. 제품 개요

업보 룰렛은 한 기기를 모임 참가자에게 차례로 전달해 질문 응답을 받고, 독박 결제 담당자를 추첨하거나 총액을 점수 비율로 나누는 모바일 정산 유틸리티다. 실제 결제·송금·베팅 기능은 제공하지 않는다.

### 사용자 문제와 가치

모임의 정산은 단순한 균등 분할이나 무작위 추첨으로 끝나는 경우가 많다. 참가자들은 질문에 직접 응답하고 그 결과가 당첨 확률 또는 분담 비율에 반영되는 과정을 함께 보며, 최종 정산을 재미있고 이해하기 쉽게 확인할 수 있다.

### 대상 사용자

- 친구·연인·직장 동료와 식사·모임 비용을 정산하는 사람
- 한 기기를 돌아가며 사용하고, 계정 생성 없이 즉시 진행하려는 모임

## 2. 목표와 성공 조건

- 로그인 없이 모바일 웹과 앱인토스에서 모드 선택부터 결과 공유까지 진행한다.
- 2~12명의 참가자와 독박 룰렛·업보 N빵 두 모드를 지원한다.
- 원문 점수 규칙으로 독박 확률과 차등 부담을 계산한다.
- N빵 결과는 입력 총액과 정확히 같고, 모든 부담액은 정수·0 이상이다.
- 응답 전달 과정에서 앞 참가자의 질문·선택·점수를 다음 참가자에게 노출하지 않는다.
- 참가자는 결과를 확인하고 텍스트 공유 또는 복사를 시도할 수 있다.

## 3. 범위

### MVP 포함

F01 모드 선택, F02 참가자 설정·랜덤 닉네임, F03 N빵 금액 입력, F04 질문 응답·점수 계산, F05 독박 룰렛 및 결과, F06 N빵 결과, F07 결과 공유·복사, F08 동일 참가자 재진행·새 참가자 시작.

### 제외

계정·서버·DB·모임 기록 저장, 실제 결제·송금, 온라인 멀티플레이, 친구 초대·방 생성, 사용자 정의/AI 질문, 광고·수익화, 영수증 이미지, 시즌 테마, 복잡한 사운드 효과.

## 4. 제품 규칙

| 구분 | 기준 | 상태 |
|---|---|---|
| 참가자 | 2~12명, 등록 순서 유지, 닉네임 입력·수정·추가·삭제·랜덤 생성, 중복·빈 값 불가 | 인원과 기능은 원문 요구. 1~20자·정규화는 인수인계 초안(Q05) |
| 금액 | 원화 정수, 0원 이하 불가, 천 단위 표시, 독박 모드에서 입력 단계 생략 | 원문 요구. 최대 99,999,999원은 초안 상한(Q05) |
| 질문 응답 | 원문 질문을 체크박스로 다중 선택, 선택 해제, 한 문항 중복 불가, 0개 선택으로 완료 가능 | 원문 요구. 최종 문항 목록은 Q01 |
| 점수 | sᵢ = max(20, 100 + 선택 문항 점수 합계). 점수가 높을수록 당첨 확률·부담 증가 | 원문 요구. 점수 상한과 최종 질문은 Q01 |
| 독박 확률 | sᵢ / Σs × 100. 확률 표시는 소수 둘째 자리까지 가능하며 추첨은 원점수 비율 사용 | 원문 요구 |
| 정산 금액 | 총액을 점수 비율로 분배하고 부담합계 검증 | 원문 요구. 원 단위 배분 공식은 Q02 |
| 응답 프라이버시 | 참가자 호출 시 이전 답변·점수 비노출, 다음 참가자가 시작을 눌러 응답 | 원문 요구와 UX 구체화 |
| 결과 공개 | F06 주요 질문은 결과에 제공. 추천안은 기본 비공개, 참가자가 공개를 선택한 경우에만 표시 | 정책 제안 Q03 |
| 공유 | 독박: 참가자·당첨자·당첨자 점수·확률·서비스 링크. N빵: 총액·참가자별 부담액·링크. 질문은 제외 | 원문 공유 항목. 질문 제외는 PM 기본안 |
| 재진행 | 동일 참가자: 모드·명단 유지, 응답·점수·결과 초기화. 새 참가자: 모드 선택으로 이동하고 참가자 정보 초기화 | 동일 참가자 규칙은 원문. 금액 유지·새로고침 동작은 Q06 |
| 저장 | 서버·DB 없이 클라이언트 처리 | 원문 기술 제약. 새로고침 복구 방식은 Q06 |

## 6. 비기능 요구사항

- iOS Safari, Android Chrome, 일반 모바일 웹, 앱인토스 웹뷰를 지원한다.
- 모바일 우선. 12명 목록과 금액을 읽고 조작할 수 있으며 색상 외 번호·텍스트·테두리로 구분한다.
- 터치 조작 영역 48×48 CSS px 이상을 UX 수용 기준으로 둔다. 기존 디자인 토큰 확인 후 맞춘다.
- 하단 CTA는 시스템 안전 영역과 키보드를 침범하지 않는다. 확대와 작은 화면에서 가로 넘침 없이 동작한다.
- 동작 감소 설정에서 룰렛 회전·장식 모션을 정적 상태로 대체하고 같은 결과를 제공한다.
- 응답 원문은 공유 텍스트와 링크에 넣지 않는다. 로그·분석에 응답 내용을 수집하지 않는다.
- 오류는 원인과 다음 행동을 함께 안내하고 입력을 보존한다. 추첨·정산 결과가 이미 확정됐다면 재시도 중 덮어쓰지 않는다.

## 7. 핵심 완료 조건

1. 두 모드 모두 2명과 12명으로 설정·질문 응답·결과까지 완료된다.
2. 빈 이름, 중복 이름, 참가자 경계, 금액 경계, 0개 선택과 최저점 경계가 명시된 규칙대로 처리된다.
3. 이전 참가자의 답변·점수가 화면과 접근성 트리에서 제거된 뒤 다음 참가자에게 전달된다.
4. 룰렛 버튼 연타·복귀에도 한 라운드에서 당첨자를 한 번만 뽑고 표시 결과와 일치시킨다.
5. N빵은 채택한 Q02 공식에 따라 정수·비음수·총액 일치를 만족한다.
6. 공유·복사 결과에 질문과 응답이 없고, 필수 공유 항목은 유지된다.
7. 재진행의 유지·초기화 범위와 새로고침 정책은 Q06 결정 후 일관되게 구현된다.
8. 코드·디자인 시스템 미확인 상태이므로 구현 전 개발 환경을 확인하고 기존 체계를 우선 사용한다.
