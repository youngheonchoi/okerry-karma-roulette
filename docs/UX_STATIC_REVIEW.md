## 1. 디자인 목표

모바일에서 참가자 차례를 명확히 전달하고 개인 응답을 가린다. 48×48px 조작, 오류 복구, 결과 인지, 재시작 범위 및 큰 글자·안전 영역의 계약을 확인한다. 48px과 8px 간격은 프로젝트 수용 기준이며 앱인토스 공식 수치로 인용하지 않는다.

Q01~Q08은 결정 완료가 없다. `src/policy.ts:34~38`의 questions·inputs·restart는 null이다. 현재 접근 가능한 경로는 모드 선택→참가자 편집→N빵 총액 초안 입력이며 응답 시작은 차단된다. Q02 정산 보류, Q03 질문 비공개, Q07 공유·복사 보류는 이번 상위 업무에 맞는 처리다. 이를 결함으로 계산하지 않았다.

## 3. 디자인 결정 및 근거: 결함·개선 의견

### D01 · P1 · 브라우저·호스트 뒤로와 내부 전환 정책이 분리됨

- 위치: `src/App.tsx:33~47,79~82,225~226`, `src/session.ts:125~130`.
- 근거: popstate는 answering에서 가리기만 한다. history 항목 구성이나 다른 화면의 내부 back 연결이 없으며 호스트 backEvent도 연결되지 않았다. 내부 버튼은 handoff/review/result에서 새 참가자 전체 초기화만 제공한다.
- 영향: 현재 참가자/금액 편집부터 브라우저 뒤로가기로 직전 앱 단계에 가는 계약이 보장되지 않는다. 정책 확정 후에는 완료 확인·결과의 확인창, 회전 중 동일 추첨 유지 계약도 호스트 뒤로에 적용되지 않는다. 실제 OS 이탈 발생은 미실행으로 미확인이다.
- 개선: USER_FLOW 4절에 따라 브라우저·시스템·호스트 입력을 같은 화면별 전환 처리에 연결한다. UX-03/05 설정 변경은 확인 후 명단 초안을 유지한 UX-02로 돌아갈 선택을 둔다. 호스트 닫기는 허용하고 자체 뒤로와 호스트 뒤로를 중복 표시하지 않는다. 회전 중은 동일 결과 유지와 중단 확인을 연결한다.
- 수용 기준: 금액→참가자에서 초안 유지, 개인 응답→현재 사람 가림, 완료/결과→확인 취소 시 유지, 회전 중 뒤로에서 재추첨 없음. 호스트 통합은 Q08 개발 후 별도 검증한다.

### D02 · P1 · 최종 당첨자 자동 발표 경로 없음

- 위치: `src/App.tsx:28~32,102,197~201`, `src/components.tsx:69~74,117~118`.
- 근거: 결과 진입 시 초점은 '오늘의 정산 결과' h1로 이동한다. 당첨자 h2·점수·확률은 일반 텍스트이며 결과 알림 영역이나 당첨자와 연결된 초점 설명이 없다. 회전 시작에는 role=status가 있다.
- 영향: 스크린리더 사용자는 추첨 종료를 인지해도 누가 선정됐는지 직접 탐색해야 한다. SCREEN_SPEC 7절의 최종 결과 1회 발표 계약에 미달한다.
- 개선: 당첨자·점수·확률을 포함한 결과 요약을 초점 대상의 접근성 설명으로 연결하거나 유지되는 결과 알림 영역에 1회 갱신한다. 초점 설명과 live 알림을 중복 사용해 두 번 발표하지 않는다.
- 수용 기준: 일반 회전·동작 감소·앱 복귀에서 같은 당첨자를 각각 한 번 발표한다. 질문·선택 내역은 포함하지 않는다.

### D03 · P2 · 600px 이상에서 좌우 안전 영역 규칙 덮어쓰기

- 위치: `src/styles.css:40,97`, `index.html:5`.
- 근거: 기본 padding은 max(16px, env(safe-area-inset-*)); 600px 미디어 쿼리는 좌우를 24px로 고정한다.
- 조건·영향: 가로 폭 600px 이상이고 한쪽 inset이 24px를 넘는 환경에서 안전 영역보다 작은 여백이 적용된다. 노치 쪽 콘텐츠가 겹칠 가능성이 있다. 실제 호스트 inset은 미확인이다.
- 개선: 넓은 화면에서도 좌우 max(24px, 해당 safe-area inset) 관계를 유지한다. 호스트가 이미 적용한 여백과 이중 가산되지 않도록 실제 WebView 값을 대조한다.
- 수용 기준: 가로모드·좌우 비대칭 inset에서 입력·버튼·마지막 행이 가려지지 않는다. dialog의 사방 여백도 같은 조건에서 검수한다.

### D04 · P2 · 한 필드 수정으로 다른 필드 오류까지 지워짐

- 위치: `src/App.tsx:60~77,129~135`, 특히 닉네임 onChange의 `setErrors({})`.
- 재현 조건: N빵 참가자 제출로 두 개 이상의 빈값/중복 오류를 만든 뒤 한 행만 수정한다. 모든 행의 오류 문구와 aria-invalid가 사라지지만 다른 잘못된 값은 남는다. 현재 접근 가능한 화면의 문제다.
- 개선: 수정한 행 및 중복 관계에 있는 행을 재검증하고 관련 없는 오류는 유지한다. 삭제·랜덤 이름도 영향받는 행만 갱신한다.
- 수용 기준: 첫 오류 이동과 입력 보존을 유지하며, 아직 잘못된 다른 필드의 오류 문구·aria-describedby·aria-invalid가 지속된다.

### D05 · P2 · 체크 후 본인 점수 변경 알림 없음

- 위치: `src/App.tsx:171~178`.
- 근거: 체크박스 상태와 문항 증감값은 읽을 수 있지만 현재 점수 p는 일반 텍스트다. 체크 후 변경 점수의 알림·설명 연결이 없다.
- 개선: 점수만 담는 짧은 polite 상태 영역을 제공한다. 선택마다 초점을 옮기거나 전체 질문 목록을 다시 읽지 않는다. 가림·완료 시 해당 영역도 제거하고 전달 화면에 점수를 복사하지 않는다.
- 수용 기준: 체크/해제 뒤 계산된 본인 점수를 인지할 수 있고 다음 참가자 호출에서는 이전 점수 알림이 남지 않는다. 실제 스크린리더 알림 큐는 후속 실행 검수가 필요하다.

### D06 · P2 · 같은 참가자 재진행 확인창이 N빵 금액 처리를 설명하지 않음

- 위치: `src/components.tsx:16~38`, `src/session.ts:132~140`, `src/App.tsx:217,229~230`.
- 근거: 확인창은 same 여부만 받아 모드·순서 유지와 응답 초기화만 설명한다. 실제 reducer는 Q06의 preserveAmount 값에 따라 금액 유지 또는 금액 지우기·재입력으로 나뉜다.
- 영향: 현재 Q06 null 상태에서는 N빵 같은 참가자 버튼이 차단되므로 잠재 결함이다. 정책 연결 후 금액이 지워지는지 보존되는지 확인 전에 알 수 없다.
- 개선: 승인된 금액 처리와 다음 화면을 확인창에 전달해 실제 동작과 같은 유지/초기화 설명을 표시한다. 금액 유지안을 이번 검토에서 확정하지 않는다.
- 수용 기준: Q06의 양쪽 구현 분기에서 확인 문구와 상태 전이가 일치하고 취소는 금액·결과를 그대로 보존한다.

### R01 · 개선 권고 · 수동 가리기 접근 거리

- 문항 전체 뒤에만 '화면 가리기'가 있어 긴 질문 목록 중간에서는 스크롤이 필요하다. 상단에도 같은 보조 행동을 제공하거나 안전 영역을 고려한 지속 접근 수단을 검토한다. 48×48px·간격 8px을 유지하고 질문·완료 CTA를 덮지 않는다. 명세의 배치 의무 위반으로 판정하지 않았다.

### R02 · 개선 권고 · 응답 중 차례 정보 보완

## 5. 반응형 및 접근성 고려사항

- 1열 세로 목록과 문서 흐름 CTA, 자동 높이, 전역 줄바꿈, 입력 min-width:0은 12명·긴 이름 대응에 유리하다. 고정 CTA가 없으므로 고정 CTA 보정 여백 요구는 해당하지 않는다.
- 320px에서 본문 288px, 입력 행은 번호24+간격8+입력200+간격8+삭제48=288px다. 기존 SCREEN_SPEC 5절의 '간격16'은 두 간격의 합으로 해석한다. 코드 grid는 이 산식과 일치한다.
- 본문16px/1.5, 보조15px, 배지·룰렛 번호13px, 제목28px/32px. 본문 크기·가중치 400~700, 3px 초점선, 시스템 서체, 한국어 lang, 라이트 모드 확인. 초안 제목24px와의 차이는 가독성 결함으로 단정하지 않는다.
- 텍스트 px 지정만으로 200% 확대 실패를 단정하지 않는다. 브라우저 텍스트 확대와 시스템 글자 확대 반영은 별도 확인해야 한다. 고정24px 번호·고정48px 삭제 열, 룰렛 번호 반경98px, dialog 높이/스크롤은 확대·작은 높이에서 집중 검수한다.
- 안전 영역 기본 CSS env와 viewport-fit=cover 확인. D03을 제외한 호스트 상단바·닫기와의 실제 겹침은 미확인이다.
- 대비는 색상 정의만 확인했으며 이번 검토에서 계산 도구나 렌더를 실행하지 않았다. 대비·실제 스크린리더 낭독·터치 성공을 합격으로 표기하지 않는다.
- 후속 검수: 320/360/390/600px, 가로모드·작은 높이, 200% 텍스트, 12명·긴 닉네임·큰 금액, 키보드 열림, Tab/Enter/Space/Esc, VoiceOver/TalkBack, 숨김/복귀·뒤로. 승인된 문항·입력 정책 연결 후 시행한다.

ait 디자인 스킬은 검토 모드 C로 적용했다. G0 브랜드는 소스상 자체 보라색 토큰·시스템 서체·자체 마크로 특이사항 없음, G2 등록 자산은 범위 밖이다. G1 호스트·G4 대비/실측·G7 실제 렌더는 확인 필요, G5 오류 복구·G4 조작성은 위 결함에 따라 보완 필요다. G3 값 정의·G6 안내는 정적 확인했으며 G8 광고는 해당 없다. 사용자 지시의 코드 수정 금지와 정적 범위가 스킬의 자동 수정·실행 요구보다 우선한다.

## 6. 개발 전달 사항

1. D01·D02를 해당 흐름 활성화 전에 보완한다. D03~D06과 권고 2건은 위치·수용 기준을 바탕으로 구현 계획에 반영한다. 이 문서는 수정 적용 보고가 아니다.
2. 응답 조건부 렌더·0개 선택 완료·단일 추첨·재진행 초기화·Q02/Q03 보류 경계를 유지한다. 정책을 임의 값으로 채워 검수를 우회하지 않는다.
3. 같은 참가자 재진행 금액 처리는 Q06 승인값으로 설명과 전이를 함께 갱신한다. 결과 발표와 점수 알림은 응답 가림 시 접근성 정보까지 지우는 계약과 함께 구현한다.
4. 이번에는 화면을 생성·수정하거나 앱을 실행하지 않았으므로 화면 캡처를 만들지 않았다. 정적 참고 HTML을 실제 화면 검증 근거로 사용하지 않았다.

## 가정

- 지시된 정식 루트와 미니의 구현 보고 경로를 사용했다. 상위 경로 및 프로젝트의 AGENTS.md는 조회에서 발견되지 않았고, 파일 목록에서 별도 CONTEXT·변경 기록은 발견하지 못했다.
- 파일 열람·정적 검색·검토 문서 작성·요청된 사무실 보고 등록만 허용 범위로 해석했다. Q01~Q08 결정 권한이나 실행 허용으로 해석하지 않았다.
- 이후 화면 결함은 현 정책 상태에서 사용자가 도달한 실행 결함이 아니라, 승인된 설정을 연결할 때 활성화될 코드의 정적 결함이다. 운영 도달 가능성과 잠재 결함을 구분했다.

## 대표 확인 필요

- 이번 정적 검토에 필요한 보류 명령은 없다. 삭제·배포·push·외부 전송 명령은 계획하지 않았다. 앱 보고 첨부는 이번 업무가 요청한 내부 결과 등록에 한정한다.
- 후속 실행 검수에는 기존 구현 보고의 `npm install`, `npm run typecheck`, `npm run build`, `npm run dev -- --host 127.0.0.1` 허용이 필요하다. 이번에는 모두 실행하지 않았다. 정책 승인과 실행 허용 후 개발·QA가 수행할 항목이며 현재 승인을 요청하지 않는다.
